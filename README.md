## 2\. Поднятые сервисы — и почему именно они

| **Сервис** | **Роль в стеке**                   | **Почему именно он (а не альтернатива)**                                                                                                       |
| ---------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| MinIO      | S3-совместимое объектное хранилище | Локальная легковесная альтернатива AWS S3. Полностью совместим с S3 API, быстро разворачивается локально.                                      |
| PostgreSQL | БД для метаданных                  | Обеспечивает строгие ACID-гарантии для хранения состояния метаданных каталога.                                                                 |
| Lakekeeper | Iceberg REST Catalog               | Реализует открытый стандарт REST Catalog. Позволяет разным движкам (Trino, Spark) безопасно работать с одними таблицами без конфликтов.        |
| Trino      | SQL-движок                         | MPP-движок для интерактивной ad-hoc аналитики. Выполняет быстрые SQL-запросы без накладных расходов на инициализацию JVM (в отличие от Spark). |

### Скрипты, которыми поднимал стек

```
# MinIO — объектное хранилище
docker run -d --name lakehouse-minio -p 9000:9000 -p 9001:9001 -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin -v minio-data:/data pgsty/silo:latest server /data --console-address ":9001"

# PostgreSQL — метаданные для каталога
docker run -d --name lakehouse-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -v pg-data:/var/lib/postgresql/data postgres:17

# Lakekeeper — инициализация БД и запуск Iceberg REST Catalog
docker run --rm -e 'LAKEKEEPER__PG_ENCRYPTION_KEY=This-is-NOT-Secure!' -e 'LAKEKEEPER__PG_DATABASE_URL_WRITE=postgresql://postgres:postgres@host.docker.internal:5432/postgres' quay.io/lakekeeper/catalog:latest-main migrate
docker run -d --name lakekeeper -e 'LAKEKEEPER__PG_ENCRYPTION_KEY=This-is-NOT-Secure!' -e 'LAKEKEEPER__PG_DATABASE_URL_READ=postgresql://postgres:postgres@host.docker.internal:5432/postgres' -e 'LAKEKEEPER__PG_DATABASE_URL_WRITE=postgresql://postgres:postgres@host.docker.internal:5432/postgres' -p 8181:8181 quay.io/lakekeeper/catalog:latest-main serve

# Trino — SQL-движок с выделением 4GB памяти во избежание OOM
docker run -d --name trino -p 8080:8080 -e JAVA_TOOL_OPTIONS="-Xmx4G" -v "$(pwd)/catalog:/etc/trino/catalog" trinodb/trino:476
```

## 6\. Часть 2 — осмысление и работа с инструментами

### 6.1. Понять и объяснить

| **Вопрос**                                                                       | **Твой ответ**                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Зачем нужны большие данные и lakehouse (а не обычная БД/хранилище)?              | Обычные СУБД жестко связывают хранение и вычисления, что дорого масштабировать. Lakehouse разделяет эти слои: данные лежат в дешевом S3 в открытых форматах (Parquet), а метаданные (Iceberg) обеспечивают ACID-транзакции. Вычислять можно любым движком по необходимости. |
| Пример schema evolution на Silver: добавил/переименовал колонку — что произошло? | Iceberg обновил метаданные таблицы (записал новую схему в манифест), физически не перезаписывая старые файлы данных. Новые файлы будут писаться с новой колонкой, а при чтении старых файлов Iceberg вернет NULL для нового поля.                                           |
| Пример скрипта восстановления данных из снапшота (time travel)                   | SELECT \* FROM bronze.lakehouse.raw_customer FOR VERSION AS OF 128504289547937565 WHERE c_custkey = 999999                                                                                                                                                                  |

### 6.2. Подключить инструмент к lakehouse

| **Инструмент** | **Почему выбрал именно его**                                                                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Apache Spark   | Индустриальный стандарт для тяжелых ETL-процессов. Имеет встроенную глубокую интеграцию с Iceberg и нативно поддерживает работу с REST-каталогами (Lakekeeper). Отлично подходит для batch-нагрузок. |

#### Скрипт развертывания Spark

```
docker run -it --rm -u root --add-host host.docker.internal:host-gateway \
  -e AWS_ACCESS_KEY_ID=minioadmin -e AWS_SECRET_ACCESS_KEY=minioadmin -e AWS_REGION=us-east-1 \
  apache/spark:3.5.3 /opt/spark/bin/spark-sql \
  --packages org.apache.iceberg:iceberg-spark-runtime-3.5_2.12:1.6.1,org.apache.hadoop:hadoop-aws:3.3.4,com.amazonaws:aws-java-sdk-bundle:1.12.262 \
  --conf spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions \
  --conf spark.sql.catalog.lakehouse=org.apache.iceberg.spark.SparkCatalog \
  --conf spark.sql.catalog.lakehouse.type=rest \
  --conf spark.sql.catalog.lakehouse.uri=http://host.docker.internal:8181 \
  --conf spark.sql.catalog.lakehouse.io-impl=org.apache.iceberg.aws.s3.S3FileIO \
  --conf spark.sql.catalog.lakehouse.s3.endpoint=http://host.docker.internal:9000 \
  --conf spark.sql.catalog.lakehouse.s3.path-style-access=true \
  --conf spark.sql.catalog.lakehouse.warehouse=bronze
```

## 7\. Выводы

Архитектура Lakehouse решает проблему вендор-лока и жесткой связи хранения с вычислениями. Использование открытого табличного формата Apache Iceberg поверх S3-хранилища MinIO позволило реализовать транзакционность, schema evolution и time travel. Применение колоночного формата Parquet в связке с алгоритмом ZSTD обеспечило высокую степень сжатия и производительность чтения, минимизируя затраты на I/O. Многослойная модель "Медальон" упростила создание отказоустойчивых пайплайнов, позволив прозрачно применять партиционирование и историчность (SCD Type 2) на уровне Silver, формируя готовые агрегаты для бизнеса на уровне Gold.
